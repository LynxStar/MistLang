# Feature Requirements: Book Chapter Policy

## Rule

Every requirements document for a new language feature that introduces user-visible syntax, semantics, or type system concepts MUST include a requirement for updating or adding a chapter in the book (`book/src/`).

## What Must Be Covered

The requirements MUST specify that the book is updated to:

1. **New chapter or section** — If the feature introduces a new concept (e.g., drop semantics, pattern matching), a dedicated chapter is added under the appropriate section (Basics, Object Model, Type System, Advanced Features, etc.).
2. **Existing chapter update** — If the feature extends an existing concept (e.g., adding a new constraint kind to generics), the relevant chapter is updated with the new material.
3. **Compiled snippets** — All code examples follow the Book Snippet Policy: `.mist` files in `book/snippets/` with corresponding `.cs` files generated by the SnippetEmitter tool.

## Requirement Template

```markdown
### Requirement N: Book Documentation

**User Story:** As a Mist developer, I want the language book to document {feature}, so that I can learn the syntax and semantics from the official reference.

#### Acceptance Criteria

1. THE book SHALL include a {chapter|section} covering {feature} with compiled code examples.
2. THE book chapter SHALL demonstrate {list key concepts the chapter must cover}.
3. All code examples SHALL be compiled snippets following the Book Snippet Policy.
4. THE book's SUMMARY.md SHALL reference the new chapter in the appropriate section.
```

## When This Does NOT Apply

- Purely internal refactoring that doesn't change user-visible behavior.
- Bug fixes that don't introduce new concepts.
- Features that only affect the compiler's internal pipeline with no user-facing syntax or semantics change.

## Applies To

- All `requirements.md` files inside `.kiro/specs/*/`
