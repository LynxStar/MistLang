## Counting and classifications

A **site** is one physical source construct: a throw statement/expression (including bare rethrow), an entire try region with its attached catches/finally, one using statement/declaration, or one lock statement. Count nested regions, nested using statements and throws inside handlers separately; they are independent constructs, not extra counts for the surrounding handler. A try with both catch and finally has one primary classification and records both obligations. Catch/finally keyword totals are also given independently, so they cannot be mistaken for omitted sites.

Each row identifies component, file, line(s), multiplicity N, concrete form/types, handler/disposal behavior, observable obligation and primary class. Only identical `using(writer.Block())` sites in one file are grouped; every starting line is explicit and N is the number of listed lines. Row count is therefore 354, while site count is 452. A template row counts one physical emission recipe, not its number of instantiations in a compiled program. `catch@N` and `finally@N` locate attached clauses in the same file. Acquisition of a disposable or lock may itself fail; release applies only after successful acquisition.

| Code | Class | Forms and equivalence limits |
| --- | --- | --- |
| B | Boundary conversion | Typed catch, broad `catch(Exception)`, bare catch, filtered catches, and ordered multi-catch regions convert library/CLR failures to diagnostics, null/false/empty/unknown, retry, or best-effort continuation. Explicit results are equivalent only if the same failure set, filter/order, diagnostics/slots/messages, partial mutations, retry timing and caller outcome are retained. Exception-throwing CLR/library calls still require a catch-capable adapter. Narrowing a broad catch is a policy change. |
| S | Internal signalling | An explicit throw is consumed by current compiler code: metadata exclusion, invalid provenance, cache timeout. An explicit failure result can replace the throw/catch pair when every caller preserves the same state, diagnostic and outcome. This does not remove exceptions raised by underlying CLR calls. |
| R | State restoration | `try/finally`, custom disposable using scopes and locks restore/clear compiler state, writer indentation, ambient context or culture, or release synchronization. Explicit cleanup is equivalent only on **every** exit, including returns, exceptions, nested cleanup failures and async completion; a success-only trailing assignment is insufficient. Locks also require the same exclusion and acquisition/release lifetime. A result type by itself supplies neither restoration nor synchronization. |
| D | Resource disposal | Using statements/declarations, cleanup catches/rethrow and finally regions release streams, JSON/PE readers, hashes, processes, providers, cross-process lock handles, staging directories and owned program values/tasks. Preserve nesting/order, flush behavior, ownership transfer, best-effort versus propagating cleanup failure, and cleanup on returns/throws. Results can carry failure but cannot replace disposal. |
| I | Invariant assertion | Explicit throws guard invalid API arguments, broken stage/model assumptions or missing witnesses. They are not intended in valid compiler operation. No row proves unreachability. A typed internal failure may replace propagation only if callers and host retain the same observable failure; silently returning ordinary data is not equivalent. |
| P | Propagated contract rejection | Additional descriptive class, using the operator's permission to choose document categories. Expected unsupported/invalid operations (malformed character/regex input, an assignment-only helper receiving a lambda, runtime missing-context/extraction/reset/switch failures) need not be impossible invariants. No local conversion is present. Replacing a public/CLR-facing exception with a result changes its API and failure behavior unless an adapter restores the exception boundary. How a port handles these is an owner choice, not settled here. |

`GenericConstraintProjector.IsMetadataFailure` means exactly `TypeLoadException`, `FileNotFoundException`, `FileLoadException`, `BadImageFormatException`, or `NotSupportedException` ([source](../../Source/Mist/Backends/CSharpTranspiler/AmbientProvider/GenericConstraintProjector.cs#L56)). Rows spell the actual filter call and additional types; bare catches are all catchable exceptions, not an inferred IO-only set. Locks on `object` use monitor semantics; `TupleNameRows.gate` is `System.Threading.Lock` and uses its scope semantics. No catch filter binding or ordered clause may be dropped merely because it resembles another row.

## Regeneration and verification

From the repository root at the recorded Mist pin, initialize the recorded Storm pin with `git submodule update --init --recursive`. Record `git rev-parse HEAD`, `git ls-tree HEAD Source/Storm.SourceGenerator`, and `git -C Source/Storm.SourceGenerator rev-parse HEAD`. Do not substitute a different Storm branch or pin. On another revision, regenerate and re-read changed sites rather than treating a moved line as proof of equivalence.

The following reproducible check first runs the required `rg` search, then uses the installed .NET 10 SDK's bundled Roslyn parser as a syntax-only audit tool to disambiguate host constructs from comments, strings and namespace directives. It does not execute the Mist pipeline, compile repository source, load compiler metadata or create code tests. The temporary tool emits only source locations; row classification and runtime payload interpretation require reading the sites and their callers/disposable implementations.

## Interpretation limits for a port

- This is a syntactic/source inventory, not an exhaustive list of operations that can throw. IO, reflection, indexing, arithmetic, regex, awaited tasks, iterator/foreach disposal and library calls can throw implicitly without a keyword site. Helpers that call `Dispose` without using/finally are described where they explain a listed boundary, not counted as invented language constructs.
- Preserve exact observed broad-versus-typed catch coverage, filter evaluation and ordering, diagnostic locations/slots/messages, failed-result counts, CLI exit 1 versus child exit code, and best-effort continuation. “Use results” is behaviorally equivalent only at an internal boundary whose callers retain these details. CLI internal-failure reporting includes exception types, messages, inner exceptions and stack traces; a different exception or stack cannot be assumed invisible.
- Cleanup can itself throw and replace a pending exception or return. Existing using scopes dispose in reverse declaration/nesting order, while `GuardChain` explicitly disposes its hoisting list in forward order. It has no nested finally to continue after a failing disposal. Preserve those actual orders; do not silently invent aggregate-exception or cleanup-continuation policy.
- `TupleNameRows.Open` closes its input stream, immediately disposes a PEReader with no metadata, and retains successful PEReaders in `images`. No explicit disposal of that retained list appears in `TupleNameRows` or `AmbientTypeProviderV2.Dispose` at this pin; the latter disposes its MetadataLoadContext. The inventory does not claim a cleanup guarantee absent from the source or introduce a fix.
- The P class describes propagation without calling it impossible: Storm's five regex throws have no local catch and its generator host has no catch; Roslyn's reaction is outside the scanned component. The assignment-only lambda helper has no production call to `AsAssignment` at this pin, but its retained API throw is still included. Character decoding rejects unsupported/malformed literal forms; no reachability claim is needed to count the source.
- Emission is a source recipe, not evidence that all generated paths execute. Runtime cleanup ordering, culture restoration, context pop and task/drop behavior were read in current source, not dynamically probed. A port strategy may change internal representation, but choosing new exception semantics, refusal diagnostics, public result APIs, cleanup guarantees, or third-party shims belongs to the owner decision MIST-1048.
