# Book Snippet Policy

## Rule

All Mist code examples in the book MUST be checked-in snippet files that compile successfully. Never use inline Mist code blocks in the markdown — always use `{{#include}}` references to files in `book/snippets/`.

## Snippet Structure

Each snippet is a complete, compilable Mist program stored at:

```
book/snippets/<section>/<chapter>/<snippet-name>.mist
```

Every `.mist` snippet MUST have a corresponding `.cs` file containing the actual compiler output:

```
book/snippets/<section>/<chapter>/<snippet-name>.cs
```

## Generating the Emitted C#

The `.cs` file MUST be generated by the SnippetEmitter tool — never hand-written. After creating or modifying any `.mist` snippet, run:

```bash
dotnet run --project tools/SnippetEmitter
```

This compiles every `.mist` file in `book/snippets/` that has a corresponding `.cs` file and overwrites the `.cs` with the actual compiler output. It reports which files were updated, unchanged, or failed.

To add a new snippet:
1. Create the `.mist` file
2. Create an empty `.cs` file at the same path (the tool only processes pairs)
3. Run the SnippetEmitter tool to populate the `.cs` file
4. If the tool reports a failure, the snippet doesn't compile and must be fixed

## Markdown Format

Use the tabbed include pattern for every snippet:

```markdown
{{#tabs }}
{{#tab name="Mist" }}
\```mist
{{#include ../../snippets/<section>/<chapter>/<snippet-name>.mist}}
\```
{{#endtab }}
{{#tab name="Emitted C#" }}
\```csharp
{{#include ../../snippets/<section>/<chapter>/<snippet-name>.cs}}
\```
{{#endtab }}
{{#endtabs }}
```

## Snippet Requirements

- Each `.mist` file MUST be a complete program: `using Standard;`, namespace, class with `Main`, etc.
- Each snippet should be small and focused — one concept per file.
- The snippet MUST compile and run without errors through the Mist CLI.
- If a feature is not yet implemented, use an inline code block with a blockquote explaining the limitation. Do NOT create a snippet file for code that doesn't compile.

## Exceptions

Inline code blocks (without `{{#include}}`) are acceptable ONLY for:

- Pseudocode or conceptual examples explicitly marked as "not Mist syntax"
- Features that are designed but not yet implemented (must be marked with a blockquote noting the limitation)
- Error message examples showing compiler diagnostics
