# Requirements Document

## Introduction

The Mist compiler currently resolves source file locations for AST nodes using a span-containment heuristic. Because AST nodes carry file-local spans (starting from offset 0 per file), and multiple files can have numerically overlapping span ranges, the heuristic can match the wrong file — producing diagnostics that point to incorrect locations (e.g., a stdlib file instead of the user's file).

This feature introduces a `NodeOrigin` discriminated union attached directly to every AST node, providing a strong, unambiguous reference to the node's source. This eliminates all span-containment heuristics and guarantees correct file attribution for diagnostics.

## Glossary

- **SyntaxNode**: The abstract base class for all AST nodes, generated by the Storm source generator. Lives in the Storm runtime types emitted by `AstEmitter`.
- **NodeOrigin**: A discriminated union (abstract record) representing where an AST node came from. Has three variants: `ParsedOrigin`, `SyntheticOrigin`, and `TestOrigin`.
- **ParsedOrigin**: A `NodeOrigin` variant indicating the node was produced by parsing a real source file. Carries a reference to the `SourceText` of that file.
- **SyntheticOrigin**: A `NodeOrigin` variant indicating the node was synthesized (e.g., desugaring, macro expansion). Carries a reference to the original `NodeOrigin` it was derived from and a reason string.
- **TestOrigin**: A `NodeOrigin` variant indicating the node was constructed in a test. No source file exists.
- **SourceText**: The existing class (`Mist.Common.Text.SourceText`) representing the contents and path of a single source file.
- **Storm_Source_Generator**: The Roslyn source generator in `Source/Storm.SourceGenerator/` that emits the lexer, parser, and AST node classes from `.storm` grammar files.
- **SemanticModelBuilder**: The class in `Source/Mist/Semantics/Model/SemanticModelBuilder.cs` that constructs the semantic model and currently uses span-containment heuristics to resolve source locations.
- **MistParser**: The parser class in `Source/Mist/Parsing/MistParser.cs` that invokes the Storm-generated parser to produce AST nodes.
- **Span_Containment_Heuristic**: The current pattern of iterating all ASTs and finding the first one whose span range contains a node's span, used to determine which file a node belongs to.

## Requirements

### Requirement 1: NodeOrigin Type Hierarchy

**User Story:** As a compiler developer, I want a well-defined origin type hierarchy for AST nodes, so that every node carries an unambiguous reference to its source.

#### Acceptance Criteria

1. THE NodeOrigin SHALL be an abstract record type with three sealed subtypes: ParsedOrigin, SyntheticOrigin, and TestOrigin.
2. THE ParsedOrigin SHALL carry a non-null reference to a SourceText instance representing the source file the node was parsed from.
3. THE SyntheticOrigin SHALL carry a non-null reference to the NodeOrigin it was derived from and a non-empty reason string describing why the node was synthesized.
4. THE TestOrigin SHALL carry no source file reference.
5. THE NodeOrigin type hierarchy SHALL be located in a namespace accessible to both the Storm runtime and the Mist compiler.

### Requirement 2: SyntaxNode Origin Property

**User Story:** As a compiler developer, I want every AST node to expose its origin, so that diagnostic infrastructure can resolve source locations without heuristics.

#### Acceptance Criteria

1. THE Storm_Source_Generator SHALL emit an `Origin` property of type NodeOrigin on the SyntaxNode base class.
2. THE SyntaxNode Origin property SHALL be settable during node construction and readable thereafter.
3. WHEN the Storm_Source_Generator emits the SyntaxNode base class, THE SyntaxNode SHALL include the Origin property alongside the existing Span property.

### Requirement 3: Parser Origin Assignment

**User Story:** As a compiler developer, I want the parser to assign ParsedOrigin to every node it creates, so that parsed nodes always know which file they came from.

#### Acceptance Criteria

1. WHEN the MistParser parses a source file, THE MistParser SHALL assign a ParsedOrigin containing the corresponding SourceText to every SyntaxNode produced.
2. THE MistParser SHALL propagate the same SourceText-based ParsedOrigin to all child nodes within a single compilation unit.
3. IF the MistParser receives a null or missing SourceText, THEN THE MistParser SHALL report an error rather than producing nodes with no origin.

### Requirement 4: Diagnostic Location Resolution via Origin

**User Story:** As a compiler developer, I want diagnostic helpers to resolve source locations directly from node origins, so that diagnostics always report the correct file.

#### Acceptance Criteria

1. WHEN a diagnostic is created for a node with ParsedOrigin, THE diagnostic infrastructure SHALL use the ParsedOrigin SourceText to resolve the file path and line/column position.
2. WHEN a diagnostic is created for a node with SyntheticOrigin, THE diagnostic infrastructure SHALL chain through the DerivedFrom reference until a ParsedOrigin is reached, then use that SourceText for location resolution, and SHALL include supplementary text describing each synthetic step traversed (e.g., "in desugared code from file.mist(10,1): for-in desugaring") so the user understands why the reported code differs from what they wrote.
3. WHEN a diagnostic is created for a node with TestOrigin, THE diagnostic infrastructure SHALL use a fallback location (e.g., `<unknown>` path and default position) without raising an error.
4. THE diagnostic infrastructure SHALL produce correct file paths when multiple source files have overlapping span ranges.

### Requirement 5: Remove Span-Containment Heuristics

**User Story:** As a compiler developer, I want all span-containment heuristics removed from the codebase, so that there is a single, reliable mechanism for resolving node-to-file mappings.

#### Acceptance Criteria

1. THE SemanticModelBuilder SHALL resolve source locations by reading the node Origin property instead of iterating ASTs to find span containment.
2. THE SemanticModelBuilder SHALL NOT contain any methods that search for a node's source file by comparing span ranges across compilation units.
3. THE TypeCheckerAnalyzer SHALL resolve source locations by reading the node Origin property instead of iterating ASTs to find span containment.
4. THE TypeCheckerAnalyzer SHALL NOT contain any methods or inline logic that search for a node's source file by comparing span ranges across compilation units.

### Requirement 6: Test Code Origin Assignment

**User Story:** As a compiler developer, I want test code that constructs AST nodes by hand to use TestOrigin, so that tests do not require source files and diagnostics degrade gracefully.

#### Acceptance Criteria

1. WHEN test code constructs SyntaxNode instances without parsing a source file, THE test code SHALL assign TestOrigin to those nodes.
2. THE TestOrigin SHALL allow diagnostic creation to succeed without throwing exceptions or requiring a SourceText instance.

### Requirement 7: Synthetic Node Origin Traceability

**User Story:** As a compiler developer, I want synthetic nodes to trace back to their original source, so that diagnostics on desugared or macro-expanded code point to the user's original code.

#### Acceptance Criteria

1. WHEN a compiler pass creates a synthetic node derived from an existing node, THE compiler pass SHALL assign a SyntheticOrigin whose DerivedFrom references the original node's Origin.
2. THE SyntheticOrigin reason string SHALL describe the transformation that produced the synthetic node (e.g., "desugaring", "macro expansion").
3. WHEN diagnostic infrastructure chains through SyntheticOrigin references, THE diagnostic infrastructure SHALL terminate at the first ParsedOrigin or TestOrigin encountered.
