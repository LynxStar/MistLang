## Mapping details

- String searches return `int?`. Callers match a present `int` before slicing; absence is `void`, never a negative index. The adapter evaluates the original CLR search once and converts only negative results to absence. Conditional access preserves absence and skips arguments for an absent receiver. Indexes and lengths count UTF-16 code units.
- Production char searches retain their parameters. The approved empty-needle and first/last-match contracts additionally use `int? IndexOf(string, System.StringComparison)` and `int? LastIndexOf(string, System.StringComparison)`. No unrelated CLR overload families are exported.
- The cache/path span searches are membership checks. `entry.Key.AsSpan().IndexOfAny(a, b, c) < 0` maps to absence from `entry.Key.IndexOfAny([a, b, c])`, or equivalent char `Contains` checks. No span materialization or handwritten search loop is necessary. `SdkDiscovery` slices `tfm[3..]`, searches that string and narrows its optional index before slicing again; the index remains relative to the sliced text.
- Ordinary substring uses map to existing ranges, including empty/end slices. Native interpolation is invariant for ordinary holes. Format/alignment syntax (`F2`, width) is not accepted by the current grammar and model, so formatted progress messages map to provider-taking runtime formatting. This preserves formatting rather than discarding it or adding a handler-based `Create` API.
- Parameterless-culture `StartsWith(string)` and `EndsWith(string)` explicitly select `InvariantCulture`. Existing `ToUpper` and the new explicit invariant case members remain invariant. Contains and Replace defaults are ordinal in the CLR and independent of process culture. Comparison-taking overloads do not promise purity because an option can explicitly request the current culture. Explicit `Ordinal`, `OrdinalIgnoreCase` and other supplied comparisons pass through unchanged; invariant collation is distinct from ordinal comparison.
- A missing formatting provider selects invariant culture; a supplied provider is preserved. Generic Join/Concat format each value through the existing invariant formatter before delegating to CLR sequence composition. These methods are not pure: enumeration and user formatting can execute user code. Null strings and separators preserve CLR handling and sequence order.
- Unicode classification uses the corresponding CLR Unicode classifiers; ASCII classifiers remain ASCII. Case mapping is invariant, and char comparison remains typed UTF-16 value ordering.
- Split retains `StringSplitOptions`, including empty-field removal and field trimming. Omitted options mean `None`. Nullable char-array separators retain whitespace splitting. Trim/TrimEnd/TrimStart preserve whitespace versus explicit character sets. Newer CLR params-span overloads used with flat arguments/collection expressions map to Mist params arrays with the same call form and results.

`TextCapabilities` banks the four historical text probes and all new declarations in the existing `AllFeaturesV2` manifest, RunDemo call and stdout baseline. It changes current culture to Turkish while checking deterministic defaults and restores it before returning; explicit French formatting remains observable.
