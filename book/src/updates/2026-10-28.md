# October 28, 2026 — Mist Goes Public

<!-- ANCHOR: edition -->
*Kickoff edition · Published October 28, 2026 · Changes from October 21–28, 2026*

Mist's repository and book are now public. This first update looks back over the past week;
regular weekly editions are planned for Monday evenings, Eastern time.

The biggest addition is support for referencing C# projects and compiled assemblies. There
are also improvements to optional type syntax, generic diagnostics, and compiler development,
alongside fixes to resource lifetimes and generated C#.

## New Language Features

### Optional Arrays of Union Values

Grouped types now accept the optional suffix. The parentheses in `(int | string)[]` make it
an array whose individual elements can be either integers or strings; without them,
`int | string[]` means a single integer or an array of strings. Adding `?` after the grouped
array makes the whole array optional. The preview shows a mixed array and its optional form.

## C# Interop

### Reference C# Projects and Assemblies

Entries in `mist.toml`'s `[references]` table can now point to `.csproj` and `.dll` files.
Referenced C# projects are built before the Mist compilation. When a C# assembly uses a Mist
library also composed into the program, the compiler emits a forwarding assembly so both
sides agree on the types' identity. The repository includes C# interop and Entity Framework
migration samples that demonstrate the arrangement.

```toml
[references]
"Bridge" = { path = "../Bridge/Bridge.csproj" }
"Vendor.Tools" = { path = "../vendor/Vendor.Tools.dll" }
```

### Deploy Native Dependencies with the Program

Native dependencies such as SQLite are now copied automatically for the target machine.
For everyday use, `mist build my-project` targets your current operating system and processor
architecture, with no extra options. Use the new `--rid` option when preparing a build for a
different OS or architecture: for example, `linux-x64` selects native dependencies for Intel/AMD
64-bit Linux, even when building on an Apple Silicon Mac.

```bash
# Build for the machine you are using.
mist build my-project

# Select dependencies for 64-bit Linux instead.
mist build my-project --rid linux-x64
```

## Improvements

### Clearer Generic Diagnostics

When different type parameters share a name, diagnostic messages now identify their declaring
type, overload, or extension method. This includes projected CLR extension methods. For
example, the two labels below identify separate type parameters named `T`, down to the
parameter lists of their declaring overloads.

```text
T of method Probe.Api.Pick(T, T)
T of method Probe.Api.Pick(T, int)
```

### Agent References Across Editors

`mist steering` installs language references into `.mist/agents/` and maintains a marked
block in `AGENTS.md`. It also updates an existing `CLAUDE.md` when appropriate, preserving
text outside the managed block. Run it from your Mist project's directory to give coding
agents the bundled language reference.

```bash
mist steering
```

## Developer Improvements

### Reproducible Parser Memoization Profiles

`tools/MemoProfile` compares parser variants, checks equivalent parse results before timing
them, and records workload and environment details. Compiler contributors can use it to
investigate memoization costs with a repeatable protocol. This addition is an investigation
tool; production memoization is unchanged.

```bash
dotnet build tools/MemoProfile -c Release
dotnet tools/MemoProfile/bin/Release/net10.0/MemoProfile.dll all \
    --out /tmp/mist-memo-profile
```

### Compiler Publication Fails on Warnings

The CLI publish scripts now treat warnings as errors, so a warning stops publication.
Metadata-only reflection sites have documented trim-analysis suppressions because trimming
the compiler does not affect the referenced assemblies being inspected. Both publish scripts
pass `TreatWarningsAsErrors` to the SDK; the command below shows that setting explicitly.

```bash
dotnet publish Source/Mist.CLI/Mist.CLI.csproj \
    -c Release -r osx-arm64 \
    -p:TreatWarningsAsErrors=true
```

## Breaking Changes

### Arrays Cannot Hold Linear or Affine Elements

Array literals and array creation now report `MIST_PA_ARRAY_ELEMENT_DISCIPLINE` for linear
or affine element types, including type parameters constrained that way. An unrestricted
array cannot enforce those elements' drop guarantees. Programs that used these arrays need
to manage the disciplined values individually or use a container that enforces their rules.

| Element discipline | Array creation |
|--------------------|----------------|
| Linear | Refused: cannot guarantee exactly one drop |
| Affine | Refused: cannot guarantee at most one drop |

### Static Abstract Members and Ref Operator Parameters Are Refused

Analysis now enforces the existing rules that abstract types cannot declare static members
and operator parameters cannot use `ref` or `readonly ref`. Programs relying on the previous
admissions must move static members to concrete types or change operators to take their
parameters by value.

| Declaration | Required adjustment |
|-------------|---------------------|
| Static member in an abstract type | Declare it in a concrete type |
| Operator with a `ref` or `readonly ref` parameter | Pass the parameter by value |
